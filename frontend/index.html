Case #1: The Midnight Ledger

DIFFICULTY: EASY TYPE: THEFT DATE: 2026-09-10
A critical financial ledger containing proprietary corporate accounting records has vanished from a secured executive office. The primary financial director was found injured, and multiple corporate executives claim inconsistent alibis.
💡 SQL Concept Focus: SELECT & WHERE (Difficulty: EASY)
Filter suspect movements and timestamps using WHERE predicates to isolate suspect opportunities.
SELECT * FROM access_logs WHERE room = 'Executive Office';

Mandatory Investigative Objectives:

  • ⬜ Inspect Evidence: Cross-reference fingerprints, security cards, and discarded items recovered on scene.
  • ⬜ Query Access Logs: Filter access logs, phone records, or transactions for the incident window.
  • ⬜ Verify Alibis: Interrogate suspects and confront them with linked evidence to expose discrepancies.
  • ⬜ Execute Warrant: Identify the guilty suspect and substantiate the motive and method beyond reasonable doubt.

🔍 2. Database Schema Reference & Table Relationships

All queries are executed against the precinct MySQL database. Case Scope Rule: Every query must filter by WHERE case_id = {CASE_ID} to access records for the active case.

Table Real Columns Keys & Relationships
suspects suspect_id, name, age, occupation, relationship_to_victim, motive, alibi, case_id PK: suspect_id. Primary entity for joins.
access_logs log_id, suspect_id, location, access_time, exit_time, case_id FK: suspect_id → suspects.suspect_id. Verifies presence.
phone_records record_id, caller_suspect_id, receiver_suspect_id, call_time, call_duration, case_id FKs: caller_suspect_id & receiver_suspect_id.
evidence evidence_id, description, location, evidence_type, date_found, case_id Forensics, access cards, and physical artifacts.
transactions transaction_id, suspect_id, amount, transaction_date, description, case_id FK: suspect_id → suspects.suspect_id. Financial motives.
timeline_events event_id, event_time, description, location, case_id Official chronology of movements on incident date.
crime_scenes scene_id, name, location, description, case_id Key locations & incident investigation points.
victims victim_id, name, age, occupation, cause_of_crime, case_id Target entity, damages incurred, or mechanism of harm.

⚡ 3. 1-Click Starter Queries & JOIN Examples

Click any button to paste directly into your active SQL query workbench:

SELECT suspect_id, name, occupation, alibi FROM suspects WHERE case_id = {CASE_ID};
SELECT s.name, a.location, a.access_time FROM access_logs a JOIN suspects s ON a.suspect_id = s.suspect_id WHERE a.case_id = {CASE_ID} ORDER BY a.access_time;
SELECT c.name AS caller, r.name AS receiver, p.call_time FROM phone_records p JOIN suspects c ON p.caller_suspect_id = c.suspect_id JOIN suspects r ON p.receiver_suspect_id = r.suspect_id WHERE p.case_id = {CASE_ID};
SELECT s.name, t.amount, t.description FROM transactions t JOIN suspects s ON t.suspect_id = s.suspect_id WHERE t.case_id = {CASE_ID} ORDER BY t.amount DESC;
SELECT evidence_type, description, location FROM evidence WHERE case_id = {CASE_ID};

🎯 4. Step-by-Step Walkthrough to Win

  1. Step 1: Read the case briefing and forensic report in Clues. Note the incident timeline and location.
  2. Step 2: Check each suspect's Alibi in Suspects (e.g. "Claims they were at home at 21:00").
  3. Step 3: Query access_logs or phone_records for that time. Look for someone who lied about their whereabouts!
  4. Step 4: Open Arrest, select the suspect, explain why their alibi fails, and click Submit Arrest Warrant.
